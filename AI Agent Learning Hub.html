Architecting Agent Memory: Session State, Vector Search, and Managed Cloud Memory

From stateless goldfish to managed Vertex memory — eight graded rungs (L0→L7): session.state, durable per-user state with DatabaseSessionService, searchable long-term memory via add_session_to_memory / search_memory, file artifacts, working-memory compaction, crash recovery, and the same agent code on managed Vertex services with zero rewrites.

🔬 Open Lab Guide ↗ skills.google original 💻 GitHub — support-memory-lab
The scenario: You play the support lead at Lumen & Co., a smart-lamp company. Your agent is Iris. Your customer is Maya, and her LumenGlow v2 flickers.

Iris starts with all five memory failures in place. You fix them — one task, one line of code at a time.
Each task: run the broken behavior → open the file → delete a # TODO: prefix → relaunch → same prompts, different world.

What you'll learn

  • tool_context.state — the channel your code reads, next to the transcript the model reads
  • LongRunningFunctionTool + FunctionResponse — parking a run for a human, answering it from another process
  • add_session_to_memory / search_memory — a write policy and a recall policy, named and written by you
  • Connecting Vertex AI Memory Bank on an Agent Engine instance you deploy yourself
  • save_artifact — giving an upload a home, extracting facts into state
  • Governed traversals and semantic search over BigQuery, embeddings generated in place
